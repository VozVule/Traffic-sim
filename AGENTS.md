# Repository guidelines

## Code clarity

- Write self-explanatory code with clear names, small focused functions, and straightforward structure.
- Keep comments and KDocs minimal. Add them only when they explain a non-obvious decision, constraint, or public contract that the code cannot express clearly.
- Do not add comments or KDocs that merely repeat what the code does.

## Commit messages

Use the format `<type>: <description>`, with a concise description of the change.

- `feat: <description>` for new functionality.
- `fix: <description>` for bug fixes.
- `chore: <description>` for maintenance, tooling, configuration, and documentation changes.

Example: `feat: add deterministic car movement`.
